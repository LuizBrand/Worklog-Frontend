## 3. O que já foi feito

### Bug 1 — Auth não persistia após refresh

**Root cause:** Race condition entre o Zustand persist middleware e o SSR do Next.js.

O `persist` middleware chama `hydrate()` sincronamente durante a avaliação do módulo. Como `localStorage` é síncrono, a hidratação termina **antes** de qualquer render do React. Quando o `useEffect` no layout tentava registrar o listener `onFinishHydration`, a hidratação já tinha terminado — o callback nunca era disparado e `hydrated` ficava `false` para sempre.

**Fix aplicado:**

1. `src/state/auth.ts` — adicionado `skipHydration: true` ao persist:

```typescript
persist(
  (set) => ({...}),
  {
    name: 'wl-auth',
    storage: createJSONStorage(() => localStorage),
    partialize: (state) => ({ acessToken: state.acessToken, refreshToken: state.refreshToken }),
    skipHydration: true, // ← novo
  },
)
```

2. `src/app/(app)/layout.tsx` — simplificado para registrar o listener **antes** de chamar `rehydrate()`:

```typescript
// ANTES (quebrado):
const [hydrated, setHydrated] = useState(() =>
  useAuthStore.persist?.hasHydrated() ?? false,
)
useEffect(() => {
  if (hydrated) return
  return useAuthStore.persist?.onFinishHydration(() => setHydrated(true))
}, [hydrated])

// DEPOIS (correto):
const [hydrated, setHydrated] = useState(false)
useEffect(() => {
  const unsub = useAuthStore.persist.onFinishHydration(() => setHydrated(true))
  useAuthStore.persist.rehydrate() // listener registrado primeiro, rehydrate depois
  return unsub
}, [])
```

**Por que funciona agora:** `skipHydration: true` impede a hidratação automática durante avaliação do módulo. O `useEffect` registra o listener primeiro, depois chama `rehydrate()` que aciona a leitura do `localStorage` e dispara o callback corretamente.

### Bug 2 — Filtros de tickets não funcionavam

**Root cause:** Mismatch entre a serialização de query params do axios e o que o Spring Boot espera.

O orval gera `FindAllTicketsParams` como objeto aninhado:
```typescript
type FindAllTicketsParams = {
  filters: TicketFiltersParams;  // { title, status, clientId, ... }
  pageable: Pageable;            // { page, size, sort }
}
```

O axios com `params` aninhado serializa como:
```
GET /tickets?filters%5Btitle%5D=x&pageable%5Bpage%5D=0
// decodificado: filters[title]=x&pageable[page]=0
```

O Spring Boot espera params flat:
```
GET /tickets?title=x&page=0&size=20&sort=updatedAt,desc
```

**Fix aplicado** — `src/lib/api.ts`, adicionado `paramsSerializer` ao axios:

```typescript
function serializeParams(params: Record<string, unknown>): string {
  const parts: string[] = []
  function collect(obj: Record<string, unknown>) {
    for (const [key, value] of Object.entries(obj)) {
      if (value === undefined || value === null) continue
      if (Array.isArray(value)) {
        for (const v of value) parts.push(`${encodeURIComponent(key)}=${encodeURIComponent(String(v))}`)
      } else if (typeof value === 'object') {
        collect(value as Record<string, unknown>) // unwrap wrappers (filters, pageable, filtersParams)
      } else {
        parts.push(`${encodeURIComponent(key)}=${encodeURIComponent(String(value))}`)
      }
    }
  }
  collect(params)
  return parts.join('&')
}

export const api = axios.create({
  baseURL,
  headers: { 'Content-Type': 'application/json' },
  paramsSerializer: { serialize: (p) => serializeParams(p as Record<string, unknown>) },
})
```

**Impacto:** Corrige filtros de tickets E filtros de clientes (`useFindAllClients` usa `{filtersParams: {...}}` — mesmo padrão).
